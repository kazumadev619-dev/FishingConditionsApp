# ADR-006: 画面のデザインは Claude Design でデザインシステムを作り、shadcn の CSS 変数に反映する

**日付:** 2026-10-17
**ステータス:** 採用済み（実装は #281）

## 決定

画面の見た目を改修するにあたり、Claude Design でデザインシステム（色、文字、余白、部品）を作る。それをデザイントークンとして、shadcn の CSS 変数（`src/app/globals.css`）と `tailwind.config.ts` に反映する。

| 項目 | 決定 |
|------|------|
| 目的 | 見た目を良くする（ブランドと世界観を作る） |
| 方向性 | 海と自然：深い青と砂の色で、落ち着いた雰囲気 |
| 作るもの | デザインシステムと、dashboard およびログイン画面のモック |
| 実装 | トークンを CSS 変数に反映する。部品（`src/components`）の構造は変えない。ダークモードは残す |
| 範囲 | デスクトップのみ。スマホ対応は #287 に切り出す。ただしデザインシステムはスマホでの利用も想定して作る |

## 理由

### 1. トークンを差し替えるだけで全ページに効く（決め手）

色の指定の大半は、すでに shadcn/ui の CSS 変数を参照している（2026-10-17 時点で `bg-primary` などのトークンが 146 箇所、`bg-blue-500` のようなハードコードが 53 箇所）。デザイントークンを `globals.css` に反映すれば、部品のコードをほとんど触らずに6ページすべての見た目が変わる。差分が小さく、見た目の変更だけをレビューすればよい。

### 2. デザインシステムを先に作ると判断がぶれない

画面ごとにモックを描くと、色や余白が画面ごとにずれていく。先にトークンと部品を決め、モックはそれを組み合わせて作る。

### 3. Claude Design はトークンと部品を一緒に管理できる

デザインシステムとモックが同じ場所にあり、コードに落とすときの元になる。デザインツールを別に契約する必要も無い。

### 4. 方向性は「海と自然」

釣りのアプリとして世界観を出しつつ、スコアや天候を落ち着いて読める配色にする。スコアの段階の色は、背景から浮いて区別できることを優先する（WCAG AA のコントラスト比を満たす）。

## 代替案

### 画面の構成から作り直す（不採用）

目的は見た目の改善であり、使い勝手に大きな不満は出ていない。構成まで変えると差分とリスクが大きくなる。dashboard の構成を変えたくなったら、別 issue にする。

### スマホ対応を同時に行う（不採用）

今はスマホ版のレイアウトが無く、作るとなるとトークンの差し替えとは別の大きな作業になる。#287 に切り出した。

### 「計器・海図」風（ダーク基調）や「ポップ」な方向性（不採用）

候補として比べた上で、ユーザーが「海と自然」を選んだ。

## 結果

- 色の指定は CSS 変数に寄せる。部品や画面に色をハードコードしない（#286 で既存のハードコードも置き換える）
- Claude Design のデザインシステムが、見た目の正となる。トークンを変えるときは、Claude Design と `globals.css` の両方を更新する
- デスクトップを先に仕上げるので、スマホでの表示は #287 が終わるまで崩れたままになりうる

## 補足: この決定を見直すべきタイミング

- スマホ対応（#287）で、トークンの差し替えだけでは足りず、部品の構造の変更が必要になったとき
- shadcn/ui をやめる、または別の UI ライブラリに移るとき
