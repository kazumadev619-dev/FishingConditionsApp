# ADR-002: docs ディレクトリ構成

**日付:** 2026-08-10
**ステータス:** 採用済み

## 決定

`docs/` を次の 5 分類で構成する。

| ディレクトリ | 用途 | 判定質問 |
|-------------|------|---------|
| `guides/` | 作業手順・運用 | コマンドを打ちながら読むか？ |
| `reference/` | 設計・仕様 | 実装が何をしているか調べるために読むか？ |
| `adr/` | 技術的決定記録 | なぜ A ではなく B を選んだかを説明しているか？ |
| `perf/` | 計測結果 | 数値の記録か？ |
| 直下 | 全体俯瞰 | 上のどれでもないか？（`README.md` と `roadmap.md` のみ） |

あわせて次を決めた。

1. `docs/_archive/` を廃止する
2. `docs/superpowers/` を git 管理外にする
3. Kubernetes の手順は `k8s/README.md` に一本化する

## 理由

### 分類を「読者の行動」で切った

役割ベース（guides / reference）は、読者ベース（新規参入者 / 運用者 / 設計者）より判定が機械的になる。
1 人開発では読者の属性が分かれないため、「今コマンドを打っているか」で分けたほうが迷わない。

### `_archive/` を廃止した

`_archive/` には 4 ファイルあったが、実態は 2 種類が混在していた。

- **現役なのに誤配置**: `authentication-diagrams.md` は `authentication.md` からリンクされており、リンク切れの原因になっていた。`api-error-handling-usage.md` も `src/lib/apiClient.ts` が現役であるため有効なドキュメントだった
- **役目を終えたもの**: 完了済み Issue の写し 2 件

前者は `reference/` に戻し、後者は削除した。git 履歴に残るため情報は失われない。
「とりあえず `_archive/` に入れる」運用は、現役ドキュメントが紛れ込んで発見されなくなる副作用のほうが大きいと判断した。

### `docs/superpowers/` を git 管理外にした

superpowers skill が生成する設計書・実装計画は、作業中の足場であってリポジトリの成果物ではない。
リポジトリに残すと、読者が「どれが現在有効なドキュメントか」を判断する負荷が上がる。

トレードオフとして設計意図がローカルにしか残らなくなるため、**恒久的に残すべき決定は ADR として `docs/adr/` に書く**運用でカバーする。本 ADR 自体がその最初の適用例である。

### Kubernetes の手順は `k8s/README.md` を正とする

`docs/guides/docker.md` §3 が kind 前提、`k8s/README.md` が Minikube 前提で、同じ目的の手順が 2 箇所で矛盾していた。
マニフェストの隣にある `k8s/README.md` のほうが更新されやすいため、そちらを正とした。

`docs/guides/docker.md` からは kind 前提の §3 と GKE 前提の §4 を削除し、`k8s/README.md` へのリンクに置き換えた。

## 影響

- 既存ドキュメントへの相対リンクは新パスに更新した（`CLAUDE.md` / `README.md` / `docs/` 配下）
- `scripts/check-doc-links.mjs` でリンク切れを検出できる
- `docs/superpowers/` 配下の既存 3 ファイルは `git rm --cached` で追跡解除した（ローカルには残存）
