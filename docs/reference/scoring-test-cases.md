# スコア計算のテストケース表

> - **状態**: 説明（参考）。期待値の出どころは [scoring-algorithm.md](./scoring-algorithm.md)（仕様（正））
> - **対応する実装**: `src/lib/scoring/`、`src/lib/utils/scoreRank.ts`（[testing-policy.md](../guides/testing-policy.md) 7節②のうち、純粋な計算の部分）
> - **最終確認**: 2026-11-22（[#426](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/426) で作成。[#446](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/446) で、テスト名の列とカバレッジ・変異テストの数値を外し、ID に改めた）

スコア計算の入力ごとに、仕様から決まる同値クラスと境界値を洗い出した表。期待値は [scoring-algorithm.md](./scoring-algorithm.md) の節から決めたもので、実装の式や出力は写していない（[testing-policy.md](../guides/testing-policy.md) 4節）。

## 読み方

- 各行の ID（例: `T-TIDE-03`）が、該当するテストの名前の先頭に `[T-TIDE-03]` の形で入っている。表からテストを探すときは `grep -rn "T-TIDE-03" src` で探す。テストの名前や場所を変えても、ID が残っていれば表は直さなくてよい
- 同値クラス: 同じ点数になる入力の範囲。1つの代表値で確かめる。点数が時間や高さの一次式で変わる区間（潮汐タイミングなど）は、同じ点数にならないので同値クラスにならない。整数の時間だけでなく、小数の時間でも式を確かめる
- 境界値: 点数が変わる境目。境目ちょうどと、そのすぐ外を確かめる
- ID を付けたテストがない行は、「テストを書かない行」にまとめた。仕様に期待値がないか、値が変わらない（同値）ためである
- 数値（カバレッジ、変異テストの結果）は、変わるものなので、この表には書かない。測った日と commit を付けて [docs/perf/](../perf/) に記録する

## 1. 潮汐スコア（0〜40点）

入力: 現在時刻（JST）、当日の満潮・干潮の時刻と高さ（cm）。式は 潮汐タイミング（0〜25）+ 潮の大きさ（0〜15）。

### 1.1 潮汐タイミング

極値（満潮・干潮の両方）のうち、現在時刻に最も近いものまでの時間 h（時間）で決まる。出どころ: 「潮汐タイミング評価」（h ≦ 2 で 25 − 6.25h、2 < h ≦ 4 で 12.5 − 6.25(h − 2)、それ以外は 0）。

| ID | 同値クラス・境界値 | 入力（極値 12:00 に対する現在時刻） | 期待値 |
|---|---|---|---|
| T-TIDE-01 | 極値ちょうど | 12:00 | 25 |
| T-TIDE-02 | 2時間以内（後） | 13:00 | 18.75 |
| T-TIDE-03 | 0〜2時間の小数の時間（一次式） | 12:30 / 13:30 / 10:45 | 21.875 / 15.625 / 17.1875 |
| T-TIDE-04 | 2時間ちょうど（前・後） | 10:00 / 14:00 | 12.5 |
| T-TIDE-05 | 2時間超〜4時間以内 | 15:00 | 6.25 |
| T-TIDE-06 | 2〜4時間の小数の時間（一次式） | 14:30 / 08:30 | 9.375 / 3.125 |
| T-TIDE-07 | 4時間ちょうど | 16:00 | 0 |
| T-TIDE-08 | 4時間超 | 17:00 | 0 |
| T-TIDE-09 | 基準が干潮 | 干潮 12:00、現在 12:00 | 25 |

### 1.2 潮の大きさ

潮位差（m）= 最も近い満潮の高さ − 最も近い干潮の高さ（cm を 100 で割る）。出どころ: 「潮の大きさ評価」の表。

| T-RANGE-04 | 1.0m の1つ下 | 99cm | 8 |
| T-RANGE-05 | 0.5m 以上 1.0m 未満 | 50cm | 8 |
| T-RANGE-06 | 0.5m の1つ下 | 49cm | 5 |
| T-RANGE-07 | 0.5m 未満 | 0cm | 5 |

出どころ: 「潮汐データがないとき」（当日の潮汐データがない、または満潮か干潮が当日にないとき 20 点）、「潮の大きさ評価」（当日のデータの中から選ぶ）。

| ID | 同値クラス | 入力 | 期待値 |
|---|---|---|---|
| T-TDAY-01 | 当日（JST）のデータがない | 前日だけ | 20 |
| T-TDAY-02 | 満潮が当日にない | 満潮 0 件 | 20 |
| T-TDAY-03 | 干潮が当日にない | 干潮 0 件 | 20 |
| T-TDAY-04 | 複数日のデータから当日を選ぶ | 前日・当日・翌日 | 当日の分だけ |

## テストを書かない行

仕様に期待値がない行と、値が変わらない（同値の）行。仕様に書いたときに、ID を付けてテストを足す。

| 項目 | 理由 |
|---|---|
| 潮汐の2時間・4時間の境目の `≦` と `<` | どちらでも同じ値になる（境目で式が連続。2時間で 12.5、4時間で 0）。同値の変異で、書けない |
| 近さが同じ極値が2つ。同じ近さで前と後ろにある場合にどちらを選ぶか | 仕様に書いていない（「最も近い」とだけ書いてあり、同じ近さの扱いがない）。[#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の2で決める |
| 日をまたぐ近さ（潮汐の 23:30 と翌 00:30 の極値、時間帯の 23:30 と 00:30 の日の出） | 仕様は「当日の潮汐データの中から選ぶ」とだけ書き、日をまたぐ近さを使うかは未決定。[#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の1で決める |
| 極値の時刻に `24:00` などの値 | 仕様に書いていない。[#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の1と一緒に決める |
| 天候の大文字小文字・前後の空白の違い（`clear` など） | 仕様に書いていない（OpenWeather は先頭大文字で返す）。[#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の4で決める |
| 天候の欠損 | 仕様の対象外（`scoring-algorithm.md` が「別 issue」と書いている）。[#417](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/417) |
| 最も良い・最も悪い要素の同点 | 仕様に書いていない。比較の `>` と `>=`、`<` と `<=` は、同点のときだけ変わる。[#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の3で決める |
| ランクの範囲外（負、100 超）、小数 | 仕様に書いていない（呼び出し側が丸めて 0〜100 に収めてから渡す） |
| 説明文のランクごとの文、最も良い条件の文、潮名・月齢の文 | 文面は仕様ではない。ランクの一文と「最も良い条件」は [#423](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/423)、潮名・月齢の行と文言の扱いは [#436](https://github.com/kazumadev619-dev/FishingConditionsApp/issues/436) の5で決める。決めるときに、仕様と一緒にテストを足す |
