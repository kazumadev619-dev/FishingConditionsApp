# reflect

> **参考元:** [pstack `reflect`](https://github.com/cursor/plugins/tree/main/pstack/skills/reflect)

セッションや直近の開発で得た知見を、スキル・ガイド・仕組みへ還元するための振り返り手順。**思いつきや1回限りの事象をプロンプトに積み上げて肥大化させない**ことが目的。

## 守ること

- **承認なしで `.agents/skills/` や `AGENTS.md` を直接書き換えない。** 対話セッションでは分類と変更案を提示して承認を待つ。夜間・無人の Orca bot 実行では、Issue または Draft PR に提案を残して止める
- **シークレットの値を読まない・転記しない。** ログに秘密情報が混ざっていても出力に含めない（`.agents/hooks/secret_guard.py` の対象と同じ）
- **重複を書かない。** 既存のスキルや `docs/guides/` に同じ趣旨の記述がある場合は、新規追記ではなく既存箇所の整理・統合を提案する

## 手順

### 1. 素材を集める

振り返る範囲に応じて、一次情報だけを読む（推測で補わない）。

- **会話ログ（セッション直後の振り返り）**:
  - Antigravity: `<appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`（`truncated_fields` がある行だけ `transcript_full.jsonl`）
  - Claude Code / Orca: 該当セッションの履歴・作業記録
- **GitHub の記録（週次・複数 PR の振り返り）**:
  - `git log --oneline -20`
  - 直近の PR レビューコメント・`pr-verifier` / `test-review` / `merge-readiness` の指摘
  - 途中で前提がズレていた Issue のコメント（`issue-delivery` ステップ0 の記録）

### 2. 「今後の判断を変える学び」だけを絞る

候補ごとに次の 3 問を通し、すべて Yes でなければ採らない。

1. **再現性があるか**: 別のタスクや別のエージェントでも再び踏みうるか（1回限りのタイポや一時障害ではないか）
2. **行動が変わるか**: これを先に知っていたら、手順・コマンド・確認先が具体的に変わるか
3. **いまの文書に無いか**: `AGENTS.md`、`.agents/skills/`、`docs/guides/`、`docs/adr/` に既に書いてあることの言い換えではないか

### 3. 3 つに仕分ける

すべての候補を次の 3 区分に分ける。

| 区分 | 意味 | 次のアクション |
|---|---|---|
| **Accepted** | 既存のスキルやガイドに反映する価値がある | 対象ファイルと最小限の編集案を提示し、承認後に反映する |
| **Rejected** | 採らない（一般化できない、既存と重複、コストに見合わない） | 採らない理由を 1 行で残し、同じ提案の再発を防ぐ |
| **Backlog** | 文章の注意書きではなく、**構造・型・lint・hook・CI・テストで物理強制すべき**もの | [`correct`](../correct/SKILL.md) スキルに渡す候補として起票・記録する |

ルール文を増やす前に、まず **Backlog（機械強制）へ逃がせないか** を必ず疑う。

## 出力の形（固定）

```markdown
## 振り返り対象
- 期間 / セッション / PR・Issue: <対象>

## Accepted（スキル・文書への反映案）
| # | 対象ファイル | 学び（何が起きたか） | 変更案（どの判断を変えるか） |
|---|---|---|---|

## Backlog（仕組み・ガード化すべき候補 → `correct` へ）
| # | 繰り返すミス | 想定する強制手段（構造 / 型 / lint / hook / CI / テスト） | 優先度 |
|---|---|---|---|

## Rejected（採用しない案）
| # | 候補 | 見送る理由 |
|---|---|---|
```
